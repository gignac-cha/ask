# 제품 요구사항 정의서 (PRD)
## WPF 브라우저 PIP(Picture-in-Picture) 윈도우

**문서 버전:** 1.0  
**작성일:** 2025-11-21  
**프로젝트 코드:** PRD-20251121-061955-WPF_Browser_PIP_Window

---

## 요약

본 문서는 브라우저 기반 PIP(Picture-in-Picture) 기능을 구현하는 WPF(Windows Presentation Foundation) 애플리케이션 개발을 위한 요구사항을 정의합니다. 이 애플리케이션은 버튼이 있는 메인 윈도우를 제공하며, 버튼 클릭 시 비디오 PIP 기능과 유사하게 윈도우 좌측 하단에 축소된 브라우저 뷰를 표시합니다. 브라우저는 1920x1080 해상도로 렌더링되지만 약 320x240 픽셀 크기로 표시됩니다.

---

## 1. 프로젝트 개요

### 1.1 문제 정의
현대 애플리케이션은 유연한 표시 옵션을 가진 임베디드 웹 콘텐츠 표시 기능을 점점 더 필요로 합니다. 사용자는 원본 웹페이지의 전체 렌더링 품질을 유지하면서 간결하고 방해가 되지 않는 방식으로 웹 콘텐츠를 볼 수 있는 기능이 필요합니다.

### 1.2 목표
- 임베디드 브라우저 기능을 가진 WPF 애플리케이션 생성
- 간결한 웹 콘텐츠 표시를 위한 PIP 스타일 오버레이 구현
- 축소된 크기로 표시하면서 고품질 렌더링(1920x1080) 유지
- 간단한 버튼 기반 인터페이스를 통한 직관적인 사용자 상호작용 제공

### 1.3 성공 기준
- 애플리케이션이 최신 브라우저 컨트롤을 성공적으로 임베드
- 브라우저가 1920x1080 전체 해상도로 지정된 URL 렌더링
- 좌측 하단 모서리에 ~320x240 픽셀로 올바르게 스케일된 디스플레이
- 성능 저하 또는 렌더링 아티팩트 없음
- 부드러운 PIP 모드 활성화/비활성화

## 2. 기술 선택 및 연구 요약

종합적인 웹 연구를 기반으로 다음과 같은 기술적 결정이 내려졌습니다:

### 2.1 브라우저 임베딩 기술: **Microsoft Edge WebView2**

**선택 근거:**
- **최신 Chromium 엔진:** Microsoft Edge (Chromium)을 활용하여 완전한 HTML5, CSS3, JavaScript 지원 제공
- **공식 Microsoft 지원:** Windows Update를 통한 정기 업데이트와 함께 퍼스트파티 지원 (에버그린 모델)
- **WPF 네이티브 통합:** NuGet 패키지(`Microsoft.Web.WebView2.Wpf`)를 통한 전용 WPF 컨트롤 제공
- **에어스페이스 문제 없음:** 레거시 WebBrowser 컨트롤과 달리 WebView2는 WPF 오버레이 요소를 적절히 처리
- **향상된 DPI 인식:** 고DPI 디스플레이 및 멀티 모니터 시나리오에 대한 우수한 지원
- **분리된 프로세스 아키텍처:** 프로세스 격리를 통한 향상된 안정성 및 보안

**고려된 대안:** CefSharp을 평가했으나 다음 이유로 거부됨:
- 큰 배포 크기(~120MB)
- 수동 업데이트 책임(에버그린 아님)
- 본 사용 사례에 불필요한 복잡성

### 2.2 해상도 vs 디스플레이 크기 구현

**핵심 기술 접근 방식:**
1. **ZoomFactor 속성:** WebView2의 `ZoomFactor` 속성이 콘텐츠 스케일링 제어
   - 적절한 줌 설정을 통해 1920x1080 뷰포트 달성 가능
   - WPF 컨트롤 차원을 통한 디스플레이 크기 제어
   
2. **WPF Transform 스케일링:** `RenderTransform`과 `ScaleTransform`을 사용한 시각적 스케일링
   - 디스플레이 크기를 줄이면서 렌더링 품질 유지
   - 공식: 스케일 = 디스플레이 크기 / 렌더 크기 ≈ 0.167 (320/1920) ~ 0.222 (240/1080)

3. **DPI 인식 구성:** 애플리케이션 매니페스트에서 `PerMonitorV2` DPI 인식 선언 필수
   - 고DPI 디스플레이에서 렌더링 문제 방지
   - 여러 모니터에서 일관된 모양 보장

### 2.3 PIP 윈도우 전략

**구현 접근 방식:**
- **메인 윈도우 내 오버레이:** 메인 윈도우 Grid 내에 브라우저 컨트롤을 절대 위치로 배치
- **가시성 토글:** XAML Visibility 속성을 통한 컨트롤 가시성 관리
- **레이어링:** Panel.ZIndex를 사용하여 브라우저가 메인 콘텐츠 위에 나타나도록 보장
- **위치 지정:** WPF 정렬 속성을 사용한 좌측 하단 정렬(HorizontalAlignment.Left, VerticalAlignment.Bottom)

## 3. 기능 요구사항

### 3.1 메인 윈도우
- **FR-1.1:** 애플리케이션은 표준 타이틀 바와 컨트롤이 있는 메인 윈도우를 표시해야 함
- **FR-1.2:** 메인 윈도우는 "브라우저 PIP 표시"(또는 이에 상응하는) 레이블이 있는 중앙 배치 버튼을 포함해야 함
- **FR-1.3:** 메인 윈도우는 합리적인 기본 크기를 가져야 함(제안: 최소 800x600)
- **FR-1.4:** 메인 윈도우는 표준 윈도우 작업(최소화, 최대화, 닫기)을 지원해야 함

### 3.2 PIP 브라우저 컨트롤
- **FR-2.1:** 애플리케이션은 WebView2 브라우저 컨트롤을 임베드해야 함
- **FR-2.2:** 브라우저는 활성화 시 `https://www.google.com/?q=ask+browser`로 이동해야 함
- **FR-2.3:** 브라우저 렌더링 해상도는 1920x1080 픽셀이어야 함
- **FR-2.4:** 브라우저 디스플레이 크기는 약 320x240 픽셀이어야 함
- **FR-2.5:** 브라우저는 메인 윈도우의 좌측 하단 모서리에 위치해야 함
- **FR-2.6:** 브라우저는 소스 콘텐츠의 16:9 종횡비를 유지해야 함

### 3.3 사용자 상호작용
- **FR-3.1:** 버튼 클릭 시 PIP 브라우저 가시성을 토글해야 함
- **FR-3.2:** 버튼 텍스트는 현재 상태를 반영하여 업데이트되어야 함("표시"/"숨기기" PIP)
- **FR-3.3:** PIP 브라우저는 애플리케이션 시작 시 초기에 숨겨져 있어야 함
- **FR-3.4:** 사용자는 표시될 때 브라우저 콘텐츠와 상호작용할 수 있어야 함(클릭, 스크롤)

### 3.4 고급 기능 (선택적 개선사항)
- **FR-4.1:** PIP 윈도우에 드래그하여 재배치 기능 추가
- **FR-4.2:** 디스플레이 크기 조정을 위한 크기 조절 핸들 추가
- **FR-4.3:** PIP 오버레이에 닫기 버튼 구현
- **FR-4.4:** PIP 위치/크기 기본 설정 저장

## 4. 비기능 요구사항

### 4.1 성능
- **NFR-1.1:** 애플리케이션 시작 시간은 3초 미만이어야 함
- **NFR-1.2:** PIP 활성화/비활성화는 즉각적이어야 함(< 200ms 인지 지연)
- **NFR-1.3:** 브라우저 렌더링은 부드러운 스크롤을 위해 30+ FPS를 유지해야 함
- **NFR-1.4:** 정상 작동 중 메모리 풋프린트는 200MB를 초과하지 않아야 함

### 4.2 호환성
- **NFR-2.1:** 애플리케이션은 Windows 11에서 실행되어야 함(주요 타겟)
- **NFR-2.2:** 애플리케이션은 Windows 10 버전 1809 이상을 지원해야 함(WebView2 요구사항)
- **NFR-2.3:** 애플리케이션은 다양한 DPI를 가진 멀티 모니터 설정을 처리해야 함
- **NFR-2.4:** 애플리케이션은 100%, 125%, 150%, 200% 디스플레이 스케일링에서 올바르게 작동해야 함

### 4.3 품질
- **NFR-3.1:** 브라우저 콘텐츠는 아티팩트나 픽셀화 없이 렌더링되어야 함
- **NFR-3.2:** 장시간 작동(8시간 이상) 중 메모리 누수 없음
- **NFR-3.3:** 애플리케이션은 네트워크 오류를 우아하게 처리해야 함(오프라인 시나리오)
- **NFR-3.4:** WebView2 런타임이 설치되지 않은 경우 적절한 오류 메시징

### 4.4 사용성
- **NFR-4.1:** UI는 Windows 11 Fluent Design 원칙을 따라야 함
- **NFR-4.2:** 모든 인터랙티브 요소는 적절한 호버 상태를 가져야 함
- **NFR-4.3:** 키보드 탐색 지원(탭 순서, Enter로 활성화)
- **NFR-4.4:** 고대비 모드 호환성

## 11. 향후 개선사항 (MVP 이후)

다음 기능은 초기 릴리스에서 **범위 외**이지만 향후 반복에서 고려될 수 있습니다:

### Phase 8: 고급 기능 (향후)
1. **드래그 가능한 PIP 윈도우:** 사용자가 PIP를 모든 모서리로 드래그 가능
2. **크기 조정 가능한 PIP:** 사용자 지정 크기 조정을 위한 크기 조절 핸들 추가
3. **URL 구성:** 사용자가 사용자 지정 URL을 지정할 수 있도록 허용
4. **다중 PIP 윈도우:** 여러 동시 브라우저 PIP 인스턴스 지원
5. **불투명도 제어:** PIP 투명도 조정을 위한 슬라이더
6. **항상 위에:** PIP를 다른 애플리케이션 위에 표시하는 옵션
7. **미니 플레이어 컨트롤:** 비디오 콘텐츠용 미디어 재생 컨트롤
8. **설정 지속성:** 세션 간 사용자 기본 설정 저장
9. **키보드 단축키:** 토글, 위치, 크기를 위한 핫키
10. **별도 윈도우로 분리:** PIP를 독립 실행형 윈도우로 변환

## 12. 용어집

| 용어 | 정의 |
|------|------------|
| **PIP** | Picture-in-Picture - 윈도우 또는 콘텐츠를 플로팅 오버레이로 표시할 수 있는 기능 |
| **WebView2** | Chromium 엔진을 사용하는 Microsoft의 최신 웹 브라우저 컨트롤 |
| **DPI** | Dots Per Inch - 스케일링에 영향을 미치는 디스플레이 해상도 측정 |
| **ZoomFactor** | 콘텐츠 확대를 제어하는 WebView2 속성 |
| **RenderTransform** | 레이아웃에 영향을 주지 않고 시각적 변환을 위한 WPF 메커니즘 |
| **에버그린** | 자동 업데이트 소프트웨어 배포 모델 (WebView2는 Windows Update를 통해 업데이트) |
| **에어스페이스 문제** | HWND 기반 컨트롤이 적절히 오버레이될 수 없는 레거시 WPF 렌더링 문제 |
| **CoreWebView2** | WebView2의 기본 Chromium 엔진 인스턴스 |
